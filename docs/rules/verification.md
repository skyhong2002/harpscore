# 怎樣才算完成

## 音樂驗收

V01 · 與指定參考版本逐段核對：曲式、主旋律、和聲、副旋律、低音、開頭節奏與尾奏。中間表格與原生音符相同，不證明表格抄對原掃描。逐聲部核對來源，包含連音的前後端；不同編制的差異先依 `docs/rules/source-verification.md` 分類。只說「聽起來像」不足以證明完整。

V02 · 每小節與每個聲部的時值正確；裝飾、連音、弱起與休止有明確處理。純排版版本比對改前後的音高、發聲起點、時值與力度，應完全一致。

V03 · 用實際樂器音域與演奏程度檢查可吹性。檢查換部是否完整接句，以及伴奏是否有承接被簡化的內容。

## 畫面驗收

V04 · 看第一頁、一般滿頁、最密段落與尾頁。放大檢查每拍減時線斷口、升降位置、x/X/0 基線、延音橫線中央、動態與和弦間距，以及靠近小節線的 0 和－。

V04a · 依 J08a 放大核對每種斷奏點／重音的水平中心是否位於所屬數字或 x／X 正上方，包含升降音、雙音、跨行與密集段落。原生 note anchor、文字框 align=center 或碰撞候選為零均不構成對齊證據。記錄實際字形左右邊界與中心誤差；修正後重新看圖，不能只檢查 y 間距。

V04b · 依 J27 逐段看實際連線形狀，尤其短音距、跨行與雙音：不能只以 up=up 判定。skyhong profile 要求全部在上方、中央高而兩端低的淺弧，不能碗形、S 形或過高。量測控制點相對線長只用來找候選；確認線身與兩端連線的相對位置，並檢查數字、升降、八度點、重音及力度的細縫。換方向與控制點後仍需正常儲存重開，完整發聲與原生連接端點不變。

V04c · 依 J29 列出當版所有跨行段，包含 renderer 自動產生、沒有手動偏移的短續段。逐段檢查上方位置、淺弧形狀與雙線的可分辨間隙；不要只驗第一段或只查 XML 已設定的段。重新分行使段數改變後，重新建立清單。

V04d · 依 J30 對同一段分開記錄四項結果：記號對準數字、記號之間的間隙、連線實際弧形、⑧虛線的音樂起訖。畫面須包含前後聲部，力度的下伸筆畫、延長記號、疊寫雙音與低八度點不能裁掉。修正一項後重查其餘三項；幾何工具的零候選不得填成四項全部通過。

V05 · 檢查開頭與結尾的小節大小、行首小節線、跨聲部垂直對齊、段落字母、頁首及頁數。MuseScore 首頁縮圖必須來自同版實際渲染，不能沿用來源五線譜縮圖。

V06 · XML 的條件正確不等於畫面正確。檢查實際線段與字形邊界；若沒有拿到新渲染，不把舊圖當成新版通過。正常 MuseScore 視窗截圖是實際渲染證據，PDF 不是唯一途徑。暫停匯出時，以同版儲存、重開及畫面檢查驗證本機譜，記錄版本雜湊和片段位置。

## 播放與交付

V07 · 在正常 MuseScore 視窗開啟並播放代表段落，核對起音、聲部平衡與音色。可播放檔與聽過的檔案要能對應到同一個版本。播放器運作、MIDI 事件比對、波形數值與實際聆聽分開標記；工具不能聽取音訊時，不宣稱已聽過。不得為了測試任意恢復使用者已暫停的音訊匯出。

V08 · 檔案存在、程序正常結束、樂譜可開啟、畫面正確與已發布是不同證據。輸出失敗停止並診斷，不因為檔案存在就宣稱輸出正常。

V09 · 交付前檢查版本清單、檔案雜湊、編制與命名。保留可編輯原檔。不要自行產生未要求的個別分部或恢復已暫停的 PDF 輸出。

V10 · 重奏換部需列出代表性 pickup 及其下一個落點，確認同一演奏者承接；另核對非主旋律部確實有內聲部或填句。雙音每音都須保留在原生發聲；五線譜逐音寫出，簡譜的非八度雙音逐音疊寫，選用八度簡寫時單數字加明確重奏記號。孔位／吹吸／滑鍵可行與真人試吹分開記錄。以實際字形檢查整組居中、八度點與上下連結線、部距及跨行延續。

V11 · 鋼琴有多個 voice 時，逐 staff、逐 voice 重新計算時間與連音；不同 voice 的同音不能互相覆蓋來源索引。獨奏鋼琴要核對旋律全曲完整，原譜伴奏的每個音是否按所記錄的改編保留。混合簡譜版與五線版的發聲事件必須相同，不能只驗第一個 voice。

V12 · 檢查八度與音色時，使用套用譜號移調、ottava 與樂器移調後的 performed pitch；不能只比較 MSCX 的 Note.pitch。Chord 的四音位及每音八度簧按多重集合核對，保留重複同音、每個起訖與原有裝飾音。先在正常視窗儲存、重開，確認實際音色資源仍正確；GM program 名稱、未啟用的舊播放欄位或容器內設定，不能單獨證明目前播放器發聲。

V13 · 檢查轉譯正確性時，證據必須含舊原譜與新版相同聲部、相同段落；只看新版不能證明抄對。把直接原圖閱讀、原生音樂差分及實際畫面檢查分別記錄，修過的音同步核對簡譜數字、升降與八度點。若具體錯段推翻舊報告，保留舊記錄並註明被哪些明確修正取代，不繼續引用它宣稱無誤。編輯提示關閉、字形正確與實際發聲正確各有獨立證據。

V14 · 排密或重新分行後重新檢查全曲實際分頁，另放大看三連音的橫桿與「3」、跨行連結線、八度虛線及力度線。原譜同段落、改前後完整音樂資料、正常儲存重開的實際畫面分別留證；三者不能互相替代。只抽查來源時明示抽查範圍，不把全頁排版檢查或原生資料相同寫成全曲來源無誤。

V15 · 元素碰撞與過寬小節依[版面診斷流程](../engraving/engraving-diagnostics.md)處理。同版實際 renderer 的幾何資料只能找出待看的位置；框相交、間距閾值或音符數不能單獨判定通過。區分合理的音桿／橫桿接觸及連線端點，逐段確認力度、八度線、顫音、連音組與和弦代號沒有侵入鄰部。依同拍號、同編制及相近內容比較小節寬度，調整後保留完整音樂事件，正常儲存重開、巡覽全頁，再以 100% 或更高倍率檢查密集與跨行段落。

V16 · 全曲時間核對須包含實際小節長度、隱藏休止符和跨小節累計起點，不只比較「第幾小節的第幾拍」。特別檢查不完整連音組、弱起及超出拍號的小節；原生解析結果仍須與正常播放器的代表段落分開驗證。五線／簡譜的原始 Note.pitch 若因譜號或 Ottava 不同而不同，先比較完整 performed pitch 多重集合，再逐項分類剩餘屬性；不得一併忽略力度、發聲時值、延音端點或裝飾音。手動琶音線長等純圖形差異可以單列，但不能把未分類差異直接排除以取得通過。

V17 · Chord 節奏角色須依曲式與來源逐段檢查：可承接鼓組般的脈動、切分、填句，也可承接弦樂的重複節奏音型。不能全曲只放固定後半拍或零散和弦，也不能為增加密度填滿原本需要留白的段落。「像爵士鼓」指節奏功能，不自動改成 swing。新增的音型明記為演奏改編，核對和聲時點、實體和弦與呼吸。

V18 · Chord 一般以完整八分、四分或附點時值寫到下一起音或真正的放氣點；不把每次起音機械地寫成十六分音符加十六分休止。只有真正細碎的節拍或有意義的斷奏才保留細分。正常儲存重開後比對附點、休止與實際 MIDI 起訖；不能只因視覺有附點就認為播放時值正確。

V19 · Chord 回放須分開檢查「有聲」、「合奏中可辨識」與「重音有對比」。核對實際啟用音色、靜音／獨奏、音量與所有簧音，再比較同一樂句的一般拍、輕帶音和選定重音。不能只把整部音量提高，或把每個音設成近似強度；可見重音須和實際回放對應。抽查重音前後的一般音，必要時比較 Chord 獨奏與全體回放。MIDI 力度及波形強弱是技術證據，不能代替聆聽，也不指定跨音色通用的固定 velocity 或分貝門檻。

V20 · 譜面文字只保留會影響演奏決定的資訊。能由節奏、力度與重音符號直接表達時，不另加「輕奏；僅 > 加重」等讀譜常識說明，也不把驗收規則、播放設定、製譜過程或檢查結果印在譜上；這些留在外部修訂紀錄。必要的特殊奏法或來源明示的演奏文字仍保留。刪除多餘文字後，核對音符、力度與回放未被連帶修改。

V21 · 使用 skyhong profile 時，列出當版每頁的實際大行起點與行數，先排除首頁和不完整末頁，再核對一般滿頁是否符合該版本選定的統一行數。不能只因總頁數減少就通過；一般頁三行／四行混用須有逐頁的特殊記譜空間證據，不能將自動分頁結果當理由。必要時調整部距、行距與分頁，保持每行小節數可依密度變化。重查最密頁、跨行連線／八度線、重音、力度與相鄰聲部的實際間隙，保留全部音高、起音、時值、力度及播放設定。四行只是此次五線譜五重奏的目標，其他編制與簡譜沿用各自的版式目標。

V22 · 自適應部距依 J31 核對：一般行保持所選正常部距，只有實際碰撞行增加最小空間。比較同版 renderer 的上下字形淨距與每頁大行數，重算不得反覆累加；手動 spacer 保留項目另列待看。分行改變後重新取樣，保留音樂資料及所有既有跨行連線。參見[操作流程](../engraving/adaptive-spacing.md)。

V23 · 使用 A08a–A08b 的 DB H. 設定時，分開驗證譜號、基礎音與八度簧回放。正常保存重開後，核對五線譜行首及換譜號處均為下方帶 8 的 F 譜號；以包含譜號、ottava 和樂器移調的 performed pitch 比對基礎音，防止重複降八度。五線／簡譜的基礎音及播放兩層須一致。核對每個基礎音 p 都有同步的 p+12，包含長音、跨小節延音及最低音區；高層相對低層為 -10 dB，不能以 velocity 差值當分貝證據。若音色已內建八度簧，查其音色層與增益，不再新增重複事件；無法確認內部平衡時記為待驗。分層增益、實際發聲與代表段落聆聽各自記錄，檢查低音為主、高八度可辨識及無重複起音。只更新規則不代表既有曲目或音色已修改、已聽驗。

## 修正一個問題時

保存使用者要求曲目的代表段落位置、profile、軟體與字型版本、預期效果、實際畫面，以及修改是否應影響播放。先對照所選參考的實際版式，再檢查新曲密集段落與全曲。公開回歸資料須有合法授權或只含最小語意案例，不公開第三方可編輯全譜；不以新寫原創四小節練習取代使用者的曲目。
