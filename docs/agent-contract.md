# Agent 的執行守則

HarpScore 的主要使用者是 AI agent。人類可閱讀同一份資料，但完成任務的標準是 agent 能依規則試做、發現問題並修正，不是只把規則摘要給人看。

## 先分類，再做譜

G01 · 使用者當次指示優先，其次是該作品的決策，之後才是選用的個人 profile 與通用預設。同一項需求有後續修正時用最後決定，不把過時要求再次套回去。偏好不是自然定律。

G02 · 編曲前讀對照來源；改排版前保存可比較的音樂事件。不能把換行、字型或音域顯示修正變成重新作曲。

G03 · 「請改譜」是執行要求。先檢查現有原檔、已核對的版本與未完成項目，做實際修正，不只回答方法。遇到缺少關鍵資訊才追問，同時繼續不依賴答案的工作。

G04 · 先在代表片段試做：選密集十六分音符、附點、切分、長音、升降和換部，而非只選最簡單的開頭。正常視窗檢查排版後，才批次套用全曲。小試做不代替使用者要求的完整曲目。

G05 · 「看起來有分組」不能當驗證。量測或觀察實際線端、字形、數字底線、和弦與力度邊界。修正後看新版畫面；過期 PDF、舊縮圖與不同檔案的截圖不是證據。

G06 · 文字／線段覆層不是獨立真相。原生音符和覆層每次都要比對；移數字也移底線端點，改長音顯示不應改發聲。如果真的縮短為呼吸，要記錄為音樂變更。

G07 · 不把演奏錯覺當成樂譜錯誤：先分辨音色起音慢、播放混音、音符起點錯誤。所有改動要能說清楚是哪一層。

G08 · 只保留當次需要的版本，先備份再整理。不覆蓋其他曲子，不丟失使用者手動修改，不清空應用偏好，不用重裝來掩蓋匯出程序問題。

G09 · 不冒充已完成：語法通過、樂譜開啟、實際渲染、正常程序結束、播放聽過、公開網站可讀，分別記錄。若某項受阻就明確說明，不用另一層證據代替。

G10 · 完成一輪後，把可重現的問題寫成小案例。通用規則進手冊；團體風格進 profile；只有某首某小節才成立的修正留在作品紀錄。不要累積一堆全曲硬編碼座標。

## 建議交付記錄

記錄來源版本、使用的 profile、樂器與音域、音樂改動、排版改動、可編輯檔清單、渲染與播放檢查、尚未通過的項目。沒有要求就不額外拆分部、不自行上傳聊天平台。
