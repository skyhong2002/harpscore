# 選擇編制與記譜版式

先閱讀 [編譜流程](workflow.md) 與 [版式驗證](tryout.md)，再依演出編制、記譜方式與所選 profile 決定起始版式。流程不綁定特定樂曲；音樂內容以當次任務的原譜、音源與編曲決策為準。

## 依編制選擇

| 編制 | 聲部配置 | 記譜方式 |
| --- | --- | --- |
| 獨奏 | 一部口琴 | 五線譜或簡譜 |
| 獨奏＋鋼琴 | 口琴與鋼琴大譜表 | 全五線譜，或口琴簡譜搭配鋼琴五線譜 |
| 二重奏 | 兩部口琴合併總譜 | 五線譜或簡譜 |
| 二重奏＋鋼琴 | 兩部口琴與鋼琴大譜表 | 依交付需求選擇，保留鋼琴原生聲部 |
| 四重奏 | 兩部半音階、低音與和弦口琴 | 五線譜或簡譜 |
| 五重奏 | 三部半音階、低音與和弦口琴 | 五線譜或簡譜 |

選擇與實際編制相符的[共用版式資產](layout-assets.md)。樣式、聲部定義與簡譜字形分開套用；[來源紀錄](../../layouts/summer/provenance.json)用來追溯版式，不指定新曲的旋律、配器或曲式。資產存在不代表該組合已完成新曲驗證。

## 建立音樂與顯示

先另存工作副本，設定曲名、作者、樂器、實際音域、拍號、速度與調性，再依已核對的來源建立音樂內容。需要沿用既有原生譜時，先檢查其版本、驗證紀錄與雜湊，不把舊曲的音符當作新曲的預設。

原生音符負責播放，文字與線段負責簡譜；改音符後必須同步覆層，再在 MuseScore 檢查每拍減時線斷口、低八度點與力度、和弦、行首及結尾。鋼琴維持大譜表與獨立聲部。這不是自動轉譜外掛。

## 驗證後完成全曲

保存可編輯譜、音樂事件與驗證紀錄。既有驗證只適用所列檔案與當時規則；新曲須依所選 profile 與最新規則，先檢查代表段落，再完成全曲並依 [檢查與交付](../rules/verification.md) 提供證據。
