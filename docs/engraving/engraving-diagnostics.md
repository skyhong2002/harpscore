# 元素碰撞與過寬小節的診斷

`tools/articulation_centers.py` 依同一渲染時間點與同一 track 配對數字和斷奏／重音，分別量出兩者字形框的水平中心，輸出差值及局部 x 位移提案。必須先確認當版 renderer 的 Articulation 類型 ID；Ornament 不混入。沒有對應數字或多個數字水平位置不明確時跳過，不借用鄰音。數字 1、其他數字與 x／X 的字寬不同，不能以單一固定偏移代替量測。套用後重新讀幾何並看圖，尤其檢查數字上方八度點、圈 ⑧、連音組與連線；提案和中心誤差降低均不等於視覺驗收。

同一拍可能有多種原生 Segment，reader 會分列文字與音符。配對前先依頁、系統、小節、tick 合併這些列的 annotations，再限制為同一 track；不能只查事件所在的單列，也不能借用前後拍的數字。不同頁、系統或小節即使 tick 相同也不得混合。

適用五線譜、簡譜與兩者並用的重奏總譜；沿用所選 profile 的字級、部距、和弦位置與八度記法。本流程落實 [V06、V14、V15](../rules/verification.md)，不提供或假定已存在自動判斷全譜無碰撞的工具。音樂來源核對仍依 [來源驗證](../rules/source-verification.md) 另行完成。

## 先固定要驗證的版本

保存修改前的可編輯檔與雜湊，記錄 MuseScore、字型、profile、頁面大小及縮放。保留使用者手動改音；不要從舊範本重新生成而覆蓋它們。讀取目前正常視窗的實際排版，幾何資料、畫面與待交付檔必須對應同一版。重新分行或重開使排版改變後，舊頁碼與幾何不能直接當成新版證據。

若現有工具能讀出 renderer 的字形、線段、頁、系統與小節邊界，先確認座標使用同一尺度、同一頁面原點；跨頁不能只比較數值相同的座標。曲線與跨行八度線須逐段處理。若讀不到實際幾何，就直接在正常 MuseScore 視窗逐頁檢查，記錄人工觀察；不要為補資料而啟動未知轉檔器或恢復使用者暫停的匯出。

## 以幾何找候選，再看畫面

元素外框相交或距離很近只是候選：曲線外框可能包住大片空白，斜線和數字的外框也不等於實際墨跡。反過來，框未相交仍可能因距離太近而難讀。記錄候選的位置、所屬部、元素種類及涉及的鄰部，再放大確認實際字形或線段。

先排除有意接觸，但排除必須限於具體關係，不能把整類元素忽略：

| 有意接觸 | 白名單的界線 |
| --- | --- |
| 音桿連到音頭、橫桿連到其音桿 | 只限同一音符或同一連桿群；碰到鄰音或鄰部仍檢查 |
| 延音線／圓滑線接近所屬音的端點 | 只限對應起訖音附近；線身穿過數字、臨時記號或其他聲部仍是候選 |
| 連音組橫桿及數字所屬的同一組 | 數字與橫桿按樣式留斷口，不得因同組就接受壓字 |
| 按指定樣式接續的譜線與小節線 | 確認確為應連通的邊界，不能用它掩蓋文字或音頭碰撞 |

每個候選分別記為「已確認需修」「有意接觸」「畫面清楚但幾何誤報」或「仍待確認」，附位置與理由。不要以某個固定距離、零候選數或白名單數量宣稱全譜無碰撞。

放大時至少檢查：

- 力度文字與漸強弱線是否貼近自己的聲部，且不碰到下一部的音符或上一部的連線。
- `8va`／`8vb` 文字、虛線、尾鉤及跨行續段，是否屬於正確聲部；高音加線或八度點是否把八度線推到鄰部。
- `tr`、延伸波線與終點，是否碰到連線、八度線或上方部別。
- 連音組的橫桿、括號與「3」等數字，是否靠近本組音符；密集段、休止起頭及跨行位置需單獨看。
- Chord 和弦代號是否靠近本部節奏：五線譜依約定在節奏上方，簡譜依選定 profile 在節奏下方。也要看與 Bass 的間距，不能只量代號到叉叉的距離。
- 雙音上下連線、簡譜八度點、減時線及臨時記號，是否互相穿越；小節線是否跨需要連接的各部連通。

## 找出過寬的小節

先巡覽全頁，找前段稀疏而尾段擁擠、少音小節被拉長、末行單獨留下很少小節等現象。接著以**同拍號、同編制、同字級與相近內容**的小節作比較；拍號相同但裝飾音、和弦標示、換調或節奏複雜度不同，仍須分組或註記。

若取得同版幾何，列出每小節實際寬度，以及全體顯示聲部共同需要的水平位置。統計應考慮不同起音位置、最短細分、裝飾音、休止、連音組、臨時記號、和弦與其他文字；不能僅將各部音符總數相加，也不能把全休止小節當作零排版需求。全休止仍有小節時長、拍點對齊、休止或延長符號，並可能承接跨小節線段。

可以比較同組小節的寬度、寬度中位數與可見內容密度，將「較少內容卻顯著更寬」列為待看離群值。這是排序方法，不是通用密度公式或必須壓縮的門檻。遇到第一小節的樂器名／調號、長和弦名、換拍、換調、排練記號、弱起、跨行邊界或尾小節，先查明額外空間的原因。

同時看整個系統：若所有小節都被均勻拉寬，可能是固定換行過早；若只有某一小節過寬，可能是局部 stretch 或某個文字的避碰空間。即使每小節寬度都正常，部距或系統間距不均仍須在全頁處理。

直接修改 MSCX 時，先在正常視窗調整一次 layout stretch，儲存後確認當前版本真正寫出的欄位。本次 MuseScore 實測使用 Measure 的 `<stretch>`；自加的 `<userStretch>` 在儲存後被移除，不能以修改前 XML 宣稱縮排成功。即使有效 stretch 已保存，也不保證自動分行會增加小節數。可在副本用 `LayoutBreak` 的 `nobreak` 將相鄰小節保留同行、以 `line` 指定行末，實際測試多放一小節的可讀性。這是局部分行選擇，不是忽略碰撞的強制通過；需檢查最忙聲部、所有跨行線段和最終頁數。隱藏播放音符或整個 Chord 容器也不保證能釋放水平空間，不要為縮頁刪除播放聲部。

## 小幅修改，重新驗證

1. 選一段稀疏行及一段密集行試排。先查局部 stretch、強制換行／換頁、元素偏移與自動避碰，再作最小修改。少音段可試多放一小節，不能把固定每行四或五小節套遍全曲。
2. 調整後檢查該行、前後行及頁尾。不要藉由縮小全譜、刪除必要記號或改音來消除碰撞；不得把空間全分給最後一小節。
3. 比對改前後全曲 performed pitch、起音、時值、力度及 voice，保留雙音重複音、裝飾音、連音與起訖；另確認速度、力度等控制與播放設定未因排版改動而改變。若有經授權的音樂修正，單獨列出，不能混入「純排版不變」。
4. 正常儲存、關閉、重開最終檔。巡覽**所有實際頁面**，記錄頁數與各頁小節範圍；再以 100% 或更高倍率查看代表段、所有修過的位置與跨行接縫。大幅重新分行後不能只看首頁與尾頁。
5. 將「全頁巡覽」「放大細節」「來源對照」「資料差分」「實際聽音」分別記錄範圍與版本。例如一份二十頁總譜，應記全二十頁巡覽，再列出三連音、八度終點、密集雙音、特殊連音組及末頁的放大位置；不能把二十頁縮圖都看過寫成每個細節已逐一放大。

## 可沿用哪些證據

沿用舊視覺證據必須說明版本差異。如果可編輯容器僅改播放設定，已逐一確認其餘所有成員與已檢查版本完全相同，可保留既有版面證據並記錄橋接雜湊；這不代表新音量已實際聽過。若音符、文字或樣式改變，就不能套用這個理由，需驗證受影響處及可能重新流動的頁面。

公開文件只記方法與合法最小案例，不放入使用者私有路徑、第三方完整樂譜、原圖或未授權畫面。沒有同版實際 renderer 或畫面證據時，保留「待檢」；不宣稱工具已自動完成驗收。

## 實際幾何的分層提案工具

`tools/engraving_lanes.py geometry.json report.json` 讀取正常 MuseScore 幾何 reader 的 `rows`、`otherSpanners`，不改譜、不匯出媒體。座標需為同頁原點、以 staff space 表示。它按頁隔離碰撞候選，保留跨部及相鄰大行候選，並依數字／升降／八度點、連音組、重音、⑧、拍號預留垂直層。連音組數字和橫桿一起提議平移；巢狀連音組自身已壞的間距仍須另檢，不聲稱共同平移能修復它。

提案會回報侵入前一部時所需的額外間距；不可只套用記號位移而忽略此需求。此工具使用保守的外框，可能把合理相接列為候選，也未包含所有曲線墨跡及缺失元素。先視覺確認候選、在副本套用選定提案，再重新讀取幾何和巡頁。首次在實際重奏尾段已找到拍號與八度線相交；這不是全曲自動排版完成或全譜無碰撞的證明。

輸入適配目前針對既有簡譜覆層：8／8.8 pt 數字視為連音標籤，空文字且負 y 的 TextLine 視為上方連音橫桿。這些是此覆層的約定，不是 MuseScore 通用識別規則；其他編輯方式必須先更換分類器。輸出記錄輸入幾何的 SHA-256，仍需另行記錄對應譜檔雜湊。試排已證實相同位移套到另一大行可能產生新碰撞，因此提案不可直接作為全曲自動修復。

連音組內部也須檢查：依相同頁／行／聲部、水平範圍與最近垂直邊界配對標籤和橫桿；不明確的配對跳過並人工核對。先讓「3」字形離開自己的橫桿，再讓外層括號避開內層標籤。`tuplet_proposals` 只回報這些位移；重新渲染後才使用 `local_mark_proposals`，按實際水平相交範圍移動重音、八度線與拍號，避免把所有記號一起拉高。跨部檢查也包含幾乎相接的水平細縫。可見延音／圓滑線外框列為候選及避讓障礙，但曲線外框相交仍不等於墨跡相撞；端點修正必須保留原生連接音。

三連音橫桿還需避開本組數字的升降記號與八度點；括號和標籤作對應調整後重看重音。計算前一部的佔用邊界時，包含力度線及曲線等所有可見幾何，不能只計數字／文字。碰撞搜尋需涵蓋同頁相鄰大行；分頁可隔離，大行之間不能當作永不相撞。跨大行結果目前只供檢查，不自動改行距。

換行延續段須獨立量測：原生 Tie／Slur 的首段已有偏移，不代表 renderer 新產生的後段也沿用；短延續段可能回到零偏移而壓住行首數字。依該段實際上下方向、字形外框與連接音定位，僅修正受影響段，保留連音兩端及播放。移開數字後仍要檢查八度點、升降記號與鄰部，不以「曲線／數字候選已消失」代替整體通過。

行首短續線尤其不能直接複製首段的大幅向上偏移：首段為避重音而加高，續段套用後可能碰到小節數。先量出該續段、升降記號、數字與重音的實際邊界，必要時用小幅水平位移讓曲線落在數字上方的空隙；確認仍明確連向原來的音，且不碰行首文字。長續線與短續線分別試排，不套用全曲同一位移。

局部部距或大行間距修改可能使整行換頁，並改變其他頁的均分間距。每次修改後重新量測全曲同頁的跨行候選，對照前後報告區分已消除與新出現的位置；不得只重查原碰撞座標。先在候選副本迭代，再正常儲存重開，核對完整音樂事件、控制與音色設定。候選數降低只是進度，剩餘候選與未巡覽頁面仍須明確列為待檢。

沒有碰撞也可能有不均勻的大空白。`system_spacing` 以每行所有已量測字形／線段的最上、最下邊界計算行間空白，不以譜表基線距離代替。至少三行的同頁內，若某間距超過最小正間距兩倍、且多出四個 staff spaces，就列為 `review-excess-gap`；這只是可調的檢查門檻，不是強制均分。兩行頁、頁尾空白、標題與未量測元素不在此比較範圍。先檢查是否有殘留固定 spacer 或樂句分隔需要，再在副本縮減、重新量測全曲、核對受影響頁。不要為消除空白而移除記號或改音。

`accent_label_contacts` 專查同頁、同大行、同 voice 的重音與三連音數字：字形垂直範圍相交且左右間隙小於 0.35 staff space 時列為待看。這能找出尚未碰撞、卻像「3>」連成一個符號的情況。不要一律擴大所有外框的碰撞門檻，否則大量正常八度點、細線間隙也會被混入。先放大核對，再用局部提案調開，確認前一部的空間並重新量測；這個分類器僅適用目前覆層約定。

裝飾音記號不能只向上逃離障礙：移過連音橫桿可能反而撞到標籤或鄰部。`symbol_slot_above` 接受已明確核對的記號與所屬數字，試放在數字上方最近的空隙，允許向下移回橫桿下方；保持水平位置，並用同頁所有已量測元素檢查間距。空隙不足就回報阻擋項目，不猜測另一個位置、不自動拉開全譜。此函式須由呼叫者明確選定原生音符與數字的對應，不從字形相近推定語意。

實際試作中，關閉原生 autoplace 後的落點與原先框加上位移不一定相同；修改後必須重新讀 renderer，不能重複累加過期的位移。reader 的 articulation 清單可能也包含原生 Ornament，套用前須查回真正元素種類；震音等未被 reader 收錄的符號仍需畫面檢查，不能把「候選為零」當成完整覆蓋。

## 儲存後仍有效的局部修正

跨行顫音要逐段檢查。實際 MuseScore 試作中，直接寫入 Trill 父元素的 offset 未保留預期效果；正常介面移動並儲存後，位置由各個 Segment 記錄。以該 renderer 實際儲存的結構為準，重開檢查首段與續段，也檢查上方 Chord 文字，不能只把整條波線往上移。

相鄰聲部的連結線可能互相穿越，即使各自的雙音上下線安排正確。先確認每條線屬於哪個聲部及哪兩個音；依當次方向規則重新分配空間；skyhong 最新要求連線都在上方，不能再以下移到音符下方避碰，應先調整淺弧、端點或局部層距。只改方向及圖形偏移，保留原生連接端點，不能刪除看似重複的線。

密集簡譜的臨時記號可能貼到前一個數字。可先試調整該時間點的局部前置空間，而非只移動降號或擴大整個小節。在本專案使用的 MuseScore 容器中，這類間距以相關 Chord 後的 Segment/leadingSpace 儲存；其他版本或格式先用正常介面試改並檢查儲存結果，不假設 XML 結構相同。此空間會影響各部同拍對齊與整行分配，因此必須重看相鄰小節、減時線端點及分行，並核對全曲音樂資料不變。

行首小節數也要列入避碰障礙。rit.、accel. 等文字與行首數字貼合時，優先試小幅水平移動文字，保留其生效拍點；避免垂直上移後撞到上一行的和弦代號。

## 跨頁繪製重影的隔離

若放大後出現幾何 reader 找不到的額外數字，先比較同檔不同縮放與頁面排列，不能直接刪掉音符或覆層。一次本機試驗中，水平排列頁面於 200% 把下一頁的行內數字重畫到前一頁；在診斷副本僅替換疑似來源的一個數字，重影跟著改變，才確認來源。此類標記副本不得交付，正式檔保持不變。

該案例改用 Preferences → Canvas → Scroll pages → Vertical 後，正常重開原正式檔、相同倍率與片段未再出現重影。這是已驗證的本機瀏覽繞法，不是修復 MuseScore 繪製引擎，也不代表其他版本、片段或輸出皆正常。記錄原設定、檔案雜湊、倍率和核對範圍；將原生音樂與覆層內容檢查和顯示問題分開。不要用全曲改字型或移動正確音符來掩蓋尚未定位的重影。

## 短連線反曲與淺弧

原生 `up` 與實際弧向不同。此 renderer 的局部試作曾把長線的正向 o2/o3 偏移沿用到短線；短線原生弧高較小，控制點推過兩端基準後變成碗形，即使 up 仍是 up。以實際渲染線長和控制點位移比例找候選，短線與長線分開校準。沒有實際曲線路徑時，bbox 的高寬與控制點只能指出風險，不能直接證明反曲或通過。

先修弧形，再放回數字上方的空隙：減少造成反曲的控制點偏移，確認中央高於兩端；需要平緩時依實際線長小幅調整，而非全曲同一常數。端點避開升降與八度點；整體移高後也要看上一聲部的減時線。長續線還要看八度虛線與行首小節數，短續線獨立看。重音與 tie 接觸時分配不同垂直層，保持重音對準數字中心，不以橫移掩蓋。此處記錄的是可重用的診斷步驟，非已完成的全曲自動修復器。

### 跨行續段與短線的回歸檢查

以實際 renderer 列出的每條連線、每個系統段建立檢查清單，而非只找 MSCX 已有手動座標的段。未設定偏移的自動續段也可能落回數字側邊；第一段正確不能證明續段正確。對照當版畫面逐段記錄：

- 短線中央是否高於兩端，是否反曲或變成碗形；長線的控制點不可原封不動套給短線。
- 行首續段是否在所屬數字上方，沒有呈現側括號般的小鉤；其原生連接端點和隱藏八度音的延音仍存在。
- 同時出現的延音與樂句線是否各自可辨，並避開上一部減時線、自己的升降／八度點、重音及⑧虛線。只在真正共用端點附近接受合理接近。
- 力度是否仍屬於正確聲部，字形與下一部的重音、八度點之間有間隙；水平置中檢查通過不能代替這項驗收。

一次只改已辨識的圖形欄位，在正常視窗儲存重開後回看該段與鄰段。完整音樂事件、原生連接端點、時間控制及啟用中的播放設定需維持一致；此類修改不需要同步改寫五線譜的音樂內容。記錄已檢查範圍，其他頁仍保留待驗狀態。

可用 `python3 tools/connection_review.py geometry.json review.json` 建立同版幾何快照的逐段清單。它保留所有可見 Tie／Slur 段，優先標出短線控制點偏移比例偏大、非上方方向與所有續行段，包含未手動設定控制點的續段。閾值只供排序，不是形狀判定；沒有標記的段仍須看實際墨跡。工具不自動修改譜，也不由 bbox 宣稱反曲已修好。隱藏八度音的播放延音另行完整比對。

回歸案例包含短顫音連線：方向已是 up，長線沿用的控制點仍令它向下凹。修正弧形後，原本緊貼線身的⑧圈號可能變得更近，須再看圈號、線頭、重音與前一部底線的間隙。水平中心誤差為零不能抵銷這個垂直碰撞；不把兩種檢查合併為單一通過旗標。

另一個續段回歸案例：跨頁後的第三部連線本來已是上方弧，但右端貼到最後一音的降記號。為該續段單獨設定垂直位置和較淺的控制點後，須同時確認右端離開降記號、左端仍在自己的數字上方，以及中央沒有上移撞到第二部減時線。不要只看中央弧頂，或把上一頁第一段的參數直接複製過來。此類圖形修正保留原生連接端點；正常儲存重開後核對兩頁接續和完整發聲資料。

### 同時出現多類問題的段落

一次截圖可同時有正常的長弧、反曲的短弧、靠近重音的⑧圈號，以及壓到八度點或下一部線身的力度。先按聲部、發聲事件與實際連線段建立四欄紀錄：水平對齊、垂直間隙、弧形、範圍端點。不得只修圖中最顯眼的一條線就把整段標為通過。疊寫三度和跨行續段各自檢查；隱藏的發聲音不是多餘圖形。

力度與延長記號附近尤其看實際墨跡，而非只有基線或框中心。局部試作曾將 mp 移到行首小節線外側，使自己的低八度點、減時線和下一部延長記號分開；這是該處有空位時的選擇，不是所有力度都向左移的預設。正常儲存重開後再次檢查字形、鄰部與下一大行，並核對完整原生音樂、時間控制及啟用音色設定未變。

## 局部自適應部距

相鄰單線簡譜的跨部碰撞可接續使用[自適應部距工具](adaptive-spacing.md)：按水平相交物件計算最小部距，輸出提案與新譜副本。只加寬需要的行，保留原有手動 spacer；幾何候選、實際渲染及音樂不變三項分別驗證。
