# MuseScore 實作與本機經驗

此文件區分可重用方法與當時單曲實作。不要未經能力測試就把本機參數當成所有 MuseScore 版本的標準。

## 已用過的覆層原型

原生音符保留音高、時值、力度供播放，文字顯示固定 C 數字，TextLine 顯示減時線。原生音頭可見但透明，一個和弦只留一個透明 anchor，其餘音頭隱藏且仍可播放，避免透明音頭水平堆疊擠開節奏。

這需要完整映射 native event 到 numeral、accidental、octave dots、duration dots、extension dashes、underline endpoints 與 dynamics。修改原生音符後覆層不會自動正確；必須重建並比對。此 repository 未提供通用 MuseScore 覆層轉換器。

## 經實際畫面調過的起始參數

這些是 Summer v1.0 使用的 profile 起點，不是跨字體、版本的保證。數值是 sp，除非註明 pt。

- 數字 Avenir Next 12pt；Chord x/X/0 用 center,baseline，y=1.0。X 讀既有 velocity >=56，不改 velocity。
- 延音橫線 Avenir Next 13pt、center,baseline、y=0.741；不用 Arial 文字框垂直置中。附點 11.5pt bold。
- 減時線 y=1.32、寬 0.11、起點 offset x=0.60、終點 off2 x=2.36。native anchor 在四分拍整點 leading space 0.75，其他位置 0.4。每拍實際斷口仍須重看。
- 舊 Summer 版的 Dynamics 下方 y=3.8；Chord 在和弦 lane 更下方 y=6.2。五重奏 dynamics 9pt。這是歷史參數；最新 profile 區分簡譜代號在節奏下方、五線譜代號在上方且音桿向下。兩者都貼近自己的節奏，不能直接把舊座標套到新譜。
- 透明 anchor 的 smallNoteMag=0.6；minNoteDistance=0.55；spacingDensity=1.5。
- 最小小節寬 26；measureSpacing=2.0。依最忙聲部的數字 attack 數，至多四個用 stretch 0.72、五到七個 0.84、其餘 1.0。不是把延音點與「－」當 attacks。
- 五重奏 staff distance 6.1；二重奏 7.6；五重奏一般頁 system distance min 5.4 / max 8.9。首五重奏標題 VBox 55，三大行靠下。
- 段落 offset (-5,-3.2)，小節號對齊 barline、置中，offset (0,-0.7)。首大行有名稱，其後無名稱、無括號，保留連續 barline。
- 最後大行 fill limit 0；不額外 stretch 最後一小節，部分末頁維持正常 system pitch。

## 只對該作品成立的例外

Summer 共 105 小節。H.3 m20 第四拍提早 mf；Chord m99 用八分減少休止；m85 後的音區層次另核對原曲。m99、m102 後加例外換行，保護 m100–102 和 m103–105，因當時 MuseScore 末行放寬最小寬而把六小節擠一起。不能把這些小節號套到新曲。

## 當時 macOS 4.7.5 的限制

正常 MuseScore 視窗可用；CLI -o、-j 匯出曾在 shutdown abort，offscreen 啟動則缺少平台 plugin。該環境不再自動重試 CLI，也不壓掉系統 crash 警告。實際應用名稱或安裝路徑由 agent 在本機查，不寫死私人路徑。

若匯出或開檔造成額外程序，先檢查程序與未存檔，不把兩個 Dock icon 直接當成裝了兩套。已存檔 tab 關閉後再從同一正常視窗開其他譜，是當時可用的操作；不以此否定其他環境正常的多 tab 支援。

PDF 暫停時直接用正常 MuseScore 畫面及截圖檢查，不必另開 SVG 匯出流程。保存後重開，記錄檔案版本及片段位置。容器 ZIP timestamp、內部檔名或縮圖更新不應誤判為音樂改變；須比較有語意的音樂資料。縮圖使用同版實際首頁渲染。

## 八度簡寫與現代播放

僅把八度另一音頭設為 invisible，仍可能由它決定音桿、符尾、連音與附加線；簡譜的原生線也可能留在隱藏五線的舊高度。八度簡寫只在簡譜真實片段試作，檢查升降、連音雙端和換行；五線譜保留兩音。不把「看不見」等同於「不影響排版」，也不將局部原型當成跨曲通用實作。

不要把 stored Note.pitch 與真正播放音高混用。原生 Ottava 可能以較低的儲存音加播放移調表示來源高音；低音譜號的八度符號也須計入。舊版 Events 的裝飾音長度或 GM program 不是新版播放器完整行為。依實際 MuseScore 版本核對啟用的音色資源、現代播放及正常儲存重開，避免修好 XML 卻仍是打擊樂音色。

簡譜的可見 x／X 覆層與隱藏播放音頭分開。在本機 4.7.5，非 drum staff 的原生 cross 音頭會連動 DEAD 悶音屬性，不能只因看不見音頭就假定它只影響外觀。隱藏播放音可採 normal 音頭，由覆層保留叉叉；正常儲存、重開後逐音確認 DEAD 為 false，並保留四音位的八個簧音、節奏與延音鏈。這不代表應移除原譜真正要求的悶音。依據：[4.7.5 Note 的 HEAD_GROUP setter](https://github.com/musescore/MuseScore/blob/v4.7.5/src/engraving/dom/note.cpp)。

五線譜若需要原生叉叉節奏，可先在副本試用 `heavy-cross` 音頭，隱藏的其他簧音仍用 normal；本機 4.7.5 的候選譜經正常保存、重開後，保留了叉叉、向下音桿與原生連結線，且所有簧音的 DEAD 都為 false。這比額外建立一套靜音顯示聲部簡單，但字形粗細、附點、裝飾音與延音須看實際畫面，不能假設任何版本都相同。逐音保留四音位的八個簧音及重複同音，並另行確認 Mixer 載入的音色；音色名稱與 DEAD 檢查不等於實際聆聽。音頭 XML 名稱可查 [4.7.5 的 NoteHeadGroup 對應](https://github.com/musescore/MuseScore/blob/v4.7.5/src/engraving/types/typesconv.cpp)。

## 隱藏播放元素與乾淨編輯畫面

透明 Note／Rest 不保證其原生附點也透明。在已驗證的 4.7.5 寫入格式中，可對對應的 `NoteDot` 子物件明示 `visible=0`；保留原本的 `dots` 時值屬性，並逐項核對覆層附點及八度點。其他版本先驗證讀寫器和實際字形，不能只因 XML 看似合理便批次套用。

`noStem` 與隱藏 Note 也不保證輔助 voice 的 Beam 不被排出。多 voice 和弦播放需保留每個簧音與起訖，僅對隱藏的輔助節奏容器設定不生成 Beam；主顯示 voice 的符桿、符尾和節奏不動。不要以刪掉輔助發聲音簡化畫面。

本機 4.7.5 的原生 XML 使用大小寫明確的 `<BeamMode>no</BeamMode>`。在每個 Note 都不可見、且 `noStem=1` 的輔助 Chord 上試作；保留可見節奏 voice 的原 Beam 設定。正常保存可能移除這些輔助 voice 已失效的 Beam 物件或參照，這是預期的排版差分，仍須逐音比較完整播放事件、音色資源與其餘譜面資料。樂器或音頭重寫之後再查一次，不能只驗證早期簡譜覆層。移除 Beam 也可能改變實際小節寬度與分頁，必須重新量測；若重新分行，逐頁重查連線及八度虛線。

灰色休止、Tuplet 數字、隱藏連線與五線可能只是「顯示隱藏元素」的編輯提示。使用者要求乾淨編輯模式時，關閉該顯示並正常儲存、重開；本次已驗證的每譜設定為 `Score/showInvisible=0`。這只控制編輯提示，不能拿來掩蓋仍會印出的黑色附點或 Beam。分別比較開啟／關閉提示的畫面，記錄同一實檔雜湊。

粉紅換行／禁止斷行符號另受 View → Show → Show formatting 控制；在本機 4.7.5 對應 `Score/showUnprintable=0`。它與 Show invisible 是不同設定，關閉顯示後仍保留原生 LayoutBreak。實際試作經保存、重開，唯讀 renderer 的音符、連線與系統位置完全相同，尾頁粉紅禁止斷行圖示消失。不要為清理提示而刪除真正的換行語意。

## 排密後重新定位線條

先依最忙聲部的實際 attack 密度調整小節伸縮與每大行容量，再以正常視窗確認真正的換行。不要只由預計的 LayoutBreak 清單推論頁數或行數。原本按舊大行保存的 Slur／Tie 分段與手動控制點，換行後可能造成凹弧、尖角或續段跑位；必須依新版實際字形與大行重做定位，不能只把整條線平移。

本機 4.7.5 試作以唯讀 plugin 取得已載入譜的字形邊界與大行位置，未匯出媒體。完整走訪各小節的 segments 與所有相關聲部，不能只用第一個 track 的 cursor 取樣，否則會漏掉其他聲部獨有的起音及 tie。根 spanner 的 autoplace 關閉也不保證生成的每個 segment 都採用同樣設定；以實際 renderer 與正常儲存重開為準。這是經驗方法，不是本 repository 已提供通用 plugin 或轉譜引擎的宣告。

統計可見頁數與大行時，排除沒有父系統、尚未排版的零尺寸小節。多小節休止仍保有原生小節資料，直接對 null page／system 去重可能虛增數量；不能因此刪掉音樂事件。以實際頁尾與跳頁核對可見頁數，並將原生小節數、可見系統數分開記錄。

三連音橫桿、獨立數字標籤、八度虛線及漸強／漸弱各自保有原生時間範圍。縮短它們與本部數字的距離時，同時檢查升降記號、弧線、前一部及上一大行的末部；固定的全曲 y 值不是驗收。保存後比對有語意的資料；相同時間上的 spanner 序列或依聲部身分對應的 audio track 陣列可能只改序，不能因此忽略成員內容、錯把重複音去重，或把真正的播放改變當成格式差異。

出現在前一大行 Chord 下方的八度虛線，也可能是下一大行首部的有效 Ottava 續段。先查實際 page／system、所屬 track、起訖與前後音符，並切換編輯提示確認；不能只憑相鄰畫面位置把它當成鬼影刪掉。譜號八度、原生 Ottava 與簡譜八度重奏符號仍須分別保留其意義。

五線總譜若因固定部距而每頁只放少數系統，先在副本縮小最小部距、看實際頁數，再分開調整頁內垂直分布。本機六聲部試作由 23 頁變成 17 頁；只收緊而限制最大展開，兩系統頁仍會留下大片空白，允許部距展開後才與三系統頁同樣接近頁底。這不是固定參數或所有曲目都應三系統的規則：逐頁保留密集段的最低間距，末頁依實際內容留在上方。每次試排都核對全曲發聲、力度及連線起訖，另看三連音、Chord 代號與鄰部的實際字形。

先依版本選 Chord 的代號層：簡譜在叉叉下方，五線譜在節奏上方，兩者都貼近自己的節奏。不能把 DB H. 或下一大行的空間當成和弦文字層。簡譜代號移到下方後，原先為上方代號避讓而向下排的延音弧線可能需要改回上側；重新核對減時線、節奏附點、裝飾音、跨行續段與力度。這是排版解法，不是改音長或全曲強制翻轉連結線的規定。

文字的正 y offset 不保證實際出現在節奏下方：autoplace 仍可能把它推回上方。需要固定文字層時，先在候選檔明示該標籤的 autoplace，再量實際文字與 x/X 的字形邊界，正常儲存重開後確認。下方代號還須避開第二條減時線、D.B. 的上方升降記號及連結線；必要時只增加相鄰兩部的距離，重新分配大行間距並確認頁數，不能以新增大片留白解決。

原生重音記號依附透明音符的位置，未必靠近顯示的數字或叉叉。將代號移到下方時，同時檢查相鄰 D.B. 的重音是否佔用代號層。可依已載入 renderer 的字形邊界調整既有 articulation 的顯示 offset，使其靠近所屬音符；保留記號本身、時間錨點與播放力度，避免另加一份可見重音造成重複。

## 原生時間位置的序列化

寫入 `location/fractions`（含 Spanner 的 next／prev）時，一律明寫分子與分母，整數也保留 `/1`。例如倒退兩個全音符必須是 `-2/1`，不能寫成 `-2`。本機 MuseScore 正常開檔把後者讀成 `-2/1024`，造成超長小節；Python `Fraction('-2')` 卻讀成整數，會讓邏輯比對誤判為通過。檢查儲存的 XML，再做正常載入、儲存、重開及已載入時間線比對，不能只依賴同一個 Python 讀寫器。

小節零時點的原生拍號、譜號與調號，必須在任何會移動時間游標的覆層 `location` 之前。晚寫的拍號可能讓 renderer 先套用前一小節拍號，即使讀取器事後掃描所得的音樂資料相同。變拍、長小節、跨小節連線及負向 location 都應納入實際載入檢查。開檔有損壞或小節時值警告時，取消候選檔載入並修正，不以「仍然開啟」視為驗收。

J14 的連續小節線必須在畫面逐行確認。本機七聲部簡譜試作中，非零 `barLineSpanFrom`／`barLineSpanTo` 端點造成各部之間斷開；將相鄰顯示 staff 的 `barLineSpan` 設為 1、末部為 0，端點回到預設 0，並核對顯式 BarLine 的 span 與端點後，正常視窗才呈現連續線。不能只查 span=1 就宣稱通過；變拍小節、雙線／終止線、隱藏播放部及單聲部另看實際結果，不把不可見輔助聲部接進總譜。

## 隱藏雙音的延音與儲存驗證

簡譜用單數字加八度重奏記號時，隱藏的另一音仍需完整延音。唯讀檢查器若先排除不可見音，會漏掉這條播放鏈；分開量測可見線條與全部已載入的原生 tie。在本機 4.7.5，可逐音檢查 `tieForward` 的起訖音、track、tick 與音高，確認沒有空終點，並與儲存資料的預期連線多重集合核對。五線譜與簡譜可能用不同的儲存音高搭配 Ottava，分別建立各版基準，最後才比較 performed pitch。

新增雙音並正常保存後，renderer 可能生成升降記號、附點 ID、隱藏 TextLine 的分行段，或自動翻轉重音朝向。逐項記錄這些顯示差分；只允許已解釋的序列化變化，不籠統忽略所有音符子物件或線段。縮小對稱疊寫非八度雙音時，重新看原有重音、八度點與上下連線；移動既有重音的顯示 offset，不增加第二份重音。依 S12 保留原譜讀音與獲准加音的獨立對照。
