# 讓 agent 真正試做

首次使用、換字體或改渲染方法時，先做這個原創四小節練習。它不是 Summer，也不需要第三方譜或音源。

## 取得可開啟的音樂原稿

執行 `python3 scripts/tryout.py --out /tmp/harpscore-trial`。產生 original.musicxml、events.json、expected.json。MusicXML 是標準節奏與音高原稿，應可在 MuseScore 正常匯入；腳本驗證每部每小節四拍，但不代表已驗證你的 MuseScore 版本。

## 給 agent 的試做任務

- 在正常 MuseScore 視窗開啟 MusicXML，另存可編輯原檔，不啟動未驗證的批次匯出程序。
- 依 fixed-c profile 試做數字顯示。半音階無點 1=C5，DB H. 若加入則用 C3。檢查第一小節的附點四分與十六分，第二小節的重複升記號和還原，第三小節跨第三拍的連音，第四小節的長音及休止。
- Chord 行用 x/X/0，讀取已存在的力度；第一小節中途換和弦，最後小節即使沒變也重印起始代號。和弦代號與 dynamics 分層。
- 用四分拍斷開每組減時線，量測或放大檢查真實斷口。數字、低八度點、橫線、力度不能碰撞。
- 取得正常視窗的實際渲染，檢查頁首、小節線、字型與對齊。播放第一、三小節，確認連音與起點，不只檢查 XML。
- 記錄產生檔、應用與字型、實際檢查、未通過項目。若沒有能力操作 MuseScore，就只回報已生成來源 fixture，不宣稱試排完成。

## 音樂保持不變的檢查

events.json 與 expected.json 是 fixture 的發聲／時值參考，不是程式生成的文字版答案。重寫連音顯示可以分段音符，但實際持續音段應等價；改版面不應新增 attack、改速度、移拍或改力度。若要為呼吸縮短，先說明這是音樂改動並獲當次任務支持。

## 通過後再做全曲

以新曲最密集的段落補一次試排，再擴展完整曲目。把失敗縮小成原創最小案例送回專案，標示是通用問題、profile 差異還是某台機器的限制。不要只在文件寫「應該很清楚」而缺少成品。
